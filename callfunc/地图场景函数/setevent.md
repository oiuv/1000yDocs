# setevent

## 功能与语法

将当前玩家的指定事件标记从未完成（0）设置为已完成（1）。`getsetevent` 是保留的同义名称，两者共用相同的服务端方法。

```pascal
Str := callfunc('setevent 事件编号');
```

函数名使用小写。事件编号为 **0～19**；它是标记的编号，不是要写入的状态值，不支持通过第二个参数清零。

| 原状态 | 调用后状态 | 返回字符串 |
|---|---|---|
| 0（未完成） | 1（已完成） | `'1'`，本次首次设置成功 |
| 1（已完成） | 1（不变） | `'0'`，已经设置过 |
| 编号越界 | 不修改 | `'0'` |

返回值表示本次是否首次设置成功，不是当前状态。读取状态请用 [`getevent`](getevent.md)。

## 示例

以下假定当前玩家的 0 号标记原为 0，仅用于说明调用结果：

```pascal
Str := callfunc('getevent 0');    // '0'：尚未完成，不修改
Str := callfunc('setevent 0');    // '1'：本次设置成功
Str := callfunc('getsetevent 0'); // '0'：旧名称操作同一标记，已设置，不重复修改
Str := callfunc('getevent 0');    // '1'：仍然是已完成
```

## 使用注意

- 需要玩家发送者上下文；新旧名称均沿用原有调用条件，不新增权限或上下文处理。
- 标记按角色保存，所有 NPC 脚本共享同一角色的 20 个编号；发奖前核对编号用途，不能与其它任务重复占用。
- 函数只设置标记，不发放物品、不检查背包或任务条件；应先完成领取资格和容量检查。标记设置后，后续发奖失败不会自动回滚。
- 随角色数据正常保存、加载，不会因重复调用或重新登录自动清零。
- 参数处理沿用 `StrToIntDef(Params[0], 0)`：漏填、非整数或整数转换失败会按编号 **0** 处理。应始终明确填写有效编号，不能用错误参数测试拒绝逻辑。
- 使用新名称前须部署包含该别名的 TGS；旧程序不识别 `setevent`，会返回空字符串且不设置标记。无需修改客户端或通信版本。
